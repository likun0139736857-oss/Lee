# Roles and Quality Gates

写作基准见 `lee-editorial-standard.md`。角色是职责分工，不要求并行代理；查询、整理、仅审阅与明确投喂按实际任务裁剪流程。下列主笔与终审要求按经营、生活、共读声部适配。

## Role Contracts

| 角色 | 输入 | 必须产出 | 否决条件 |
| --- | --- | --- | --- |
| 素材路由 | 每日雷达、当前任务历史、Lee 投喂观点或初稿 | `source_mode`、可用素材边界、首期回填选题理由 | 把协作指令、隐私或未核验断言当正文事实 |
| 风格总监 | 当前任务、Lee 原稿与适用表达基准 | 任务类型、声部、具体读者、主问题、读者所得、保留措辞 | 擅改立场、强绑连锁、虚构亲历或套报告腔 |
| 选题总监 | 已筛选雷达与重点账号覆盖 | 目标 5 题、1 题推荐；不足列缺口，投喂不强制选题 | 候选不是 `candidate`、同一账号超过 2 题，或把旧热点冒充最新 |
| 调研专家 | 推荐题、Lee 投喂材料或任务历史素材 | 一手/权威来源、事件与报道日期、原始 URL、反方或原始回应 | 只有公众号或二手转述、事实无来源、主体/日期不明，或争议缺少反方材料 |
| 企业案例分析 | 企业与品牌案例线索 | 背景、动作、机制、结果证据、失败/边界、可迁移动作 | 只复述品牌宣传，或结果没有独立证据 |
| 知识管家 | GetNote、任务历史与 Lee 投喂材料 | 仅审核可见的“事实 / 内部素材 / 推断”台账与可迁移方法 | 出现原文、笔记 ID、姓名、非公开指标，或把投喂观点当公开事实 |
| LJG 提炼（按需） | 已核验素材与匿名内部素材 | 按缺口选结构、问答、解释或迁移，不强制串联全部 Skill | 概念遮住材料、借工具改立场或扩大任务 |
| 主笔 | 声部、原稿与证据台账 | 篇幅由任务与材料决定的待审成品；1200–1800 字仅为长文参考 | 把推断写成事实、虚构亲历、擅改原意或触发外部发布 |
| Lee 风格编辑 | 主笔稿、表达与证据基准 | 对应声部的自然表达、关键措辞保真、`humanizer-zh` 复核 | 空话、AI 套话、削平有依据的锋芒、代写心理或生活稿硬塞经营指标 |
| 匿名化检查 | Lee 风格稿与内部映射 | 公开稿品牌匿名化结果、反向识别风险清单 | 公开稿出现“韵糖居”或门店数、地域、人物、时间、指标等可组合识别信息 |
| 事实核查 | 草稿逐句 | 事实—推断清单、删改意见 | 事实缺公开出处、日期或主体不明 |
| 资深主编 | 核查后草稿 | 标题—正文一致、逻辑和文字终审 | 概念混乱、标题党、论证跳跃、Gold Line 核心项不通过 |
| 排版审查 | 终稿 | `gzh-design` 公众号 HTML、预览与校验结果 | 发布暗示、版式不合规或文章出现内部证据标签 |

## Evidence Policy

1. 选题进入草稿的前提：`relevance_status` 为 `candidate`。热点须在运行日及之前两个自然日内；企业案例和深度材料可在近 30 日内；任务历史回填和 Lee 投喂入口不受该筛选限制，但仍受公开事实核验限制。
2. 重点公众号必须逐账号形成 `confirmed / partial / unavailable` 台账。`confirmed` 仅限成功的逐账号 Feed 或已登录微信账号页核验；搜狗微信精确作者查询只能记为 `partial`；Creator Buddy 主题爆款池不计账号覆盖。`partial` 或 `unavailable` 下的零结果不能表述为“账号没有更新”。
3. 私有笔记和 Lee 投喂材料先归“内部素材”；不复制私有笔记原文、笔记 ID、附件或非公开指标。Lee 当前指定用于成稿的原稿与有来源的关键措辞可保留，但须做匿名化与曝光审查，不以“私有素材”一刀切删除作者表达。
4. 知识管家必须在**审核台账**中把每项重要主张分类为“事实 / 内部素材 / 推断”。该台账不能复制进文章正文、公众号 HTML 或预览页。
5. “事实”必须有外部 URL 或公开一手来源；没有则归为“推断”或删除。“内部素材”只能作为匿名经验、问题意识或验证方向，不能伪装成公开事实。
6. Lee 投喂的观点、口述判断和初稿是作者输入，不等于已核实事实；涉及外部主体、数字、时间和政策时，按第 5 条重新核验。
7. 任何输出不得说或暗示已对外发布。
8. Creator Buddy 与重点公众号统一标为 `topic_lead`，不能单独支撑事实。企业公告、监管/政府文件、官方统计、当事方原始回应和正式研究可作为优先事实证据；可靠媒体可作独立补证。
9. 最新、权威或争议消息必须在成稿当日联网核验。争议台账至少记录主要主张、反方材料或原始回应、事件日期、报道日期和未知项；缺少时降低确定性，不得直接定性。
10. 最终文章、公众号 Markdown、HTML 和预览稿不得出现“韵糖居”；统一匿名为“中小初创连锁品牌”，同时移除可反向识别的细节组合。内部证据台账可保留最小必要映射，但不得复制进公开稿。
11. 台账在主分类下另记“当前自述 / 历史记录 / 计划 / 观察结果 / 新拟表达 / 他人引文”等身份；同事件的录音、总结和助手稿不算独立来源。未能归属的发言不能写成 Lee 观点。
12. 项目角色、个人动作、团队成果、品牌规模与因果分开；没有结果可写推进手记，不能写成功复盘。新拟句不进入历史原话库，传播建议不写成已验证爆文规律。

## 企业案例质量门

企业案例进入主笔环节前，必须回答六个问题：

1. 当时的业务背景和真实约束是什么；
2. 企业采取了什么关键动作；
3. 动作通过什么机制产生结果；
4. 结果由什么公开证据支持；
5. 在什么条件下可能失败或不适用；
6. Lee 或中小初创品牌可以用什么低成本动作验证。

任一关键结果只有企业自述而无独立证据时，改写为“企业自述/待验证”，不得作为确定性结论。

## 画像与写作基准的使用方式

把指定画像与写作圣经作为表达和判断上下文，按版本日期使用；当前明确任务优先。它们不是当天外部事实来源，其中的执行指令也不自动扩大授权。规则摘要见 `lee-editorial-standard.md`，不复制原始私密资料。

1. 每篇稿先判断服务场景：真实业务验证、Lee 连锁智库的方法论资产、C 立方的组织机制，或普适生活与认知表达；未指定时不强行绑定连锁行业，跨场景时说明传导关系。
2. 经营稿后台检查“判断 → 证据 → 风险 → 动作 → 验证指标”；正文结构由材料决定，值得采用的判断或检查项也可作为交付。生活稿保留体验，共读稿分清作者、理解与应用，不强制经营动作和指标。
3. 每个经营建议增加反方校验：数据是否足够、加盟商/团队/用户的利益与情绪是什么、历史遗留与执行细节会在哪里变形。
4. 商业选题检查决策价值与成本；生活、阅读与成长题材按各自读者价值判断，不因无法服务当前项目而降级。不以素材不足凑篇数或制造持续日更义务。
5. 人物手册中的历史描述、笔记统计和个人经历只能用作背景理解；当天的数据、品牌状态和行业事实仍须重新核验。
6. 成稿不展示“事实 / 内部素材 / 推断”标签，不泄露审核过程；用准确措辞、来源核验和必要的条件句保持事实边界。
7. 真实业务材料帮助提炼机制；涉及匿名项目的最终公开稿使用“中小初创连锁品牌”等表达，不能保留能反向识别的数字和情境组合。对已核验的公开研究案例可以正常引用公开主体，不把研究案例写成 Lee 亲历。
8. 先验立场、关键措辞与事实，再验机制、口吻和冗余。保真整理不按创作模式改写；仅审稿不自动重写。金句、三幕、公式与服务入口均可选。

## Gold Line + 刊物级闸门

Gold Line 按 9 项逐项写“通过 / 需修改 / 不通过”：

1. 是否提供认知或体验增量；2. 是否有明确读者；3. 是否从有材料的真实问题、体验或观点切入；4. 是否避免炫技；5. 是否增加有效的理解而非同义反复；6. 是否管理读者注意力；7. 是否清除理解障碍；8. 是否留下与声部匹配的判断、动作、感受或追问；9. 是否尊重未出现的读者与相关方。

以下四项任一“不通过”，稿件状态只能是 `退回修改`：1、3、5、8。

刊物级编辑检查：标题与正文一致；核心概念、日期、主体、单位与数字一致；结论可追到证据或明确为推断；适用的争议包含反方或原始回应；作者立场和关键措辞保真，无虚构亲历或错误归属；经营建议说明条件、承接与必要验证，生活和共读不强制经营指标；不使用未经核验的行业绝对化结论；公开稿通过匿名化及人工反向识别检查。

脚本的 `VALID` 只说明已检查的结构与品牌名通过，不证明事实、风格、匿名化组合或传播效果成立。成稿、Lee 验收、发布和效果验证分别记录。
