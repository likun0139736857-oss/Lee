# Roles and Quality Gates

## Role Contracts

| 角色 | 输入 | 必须产出 | 否决条件 |
| --- | --- | --- | --- |
| 素材路由 | 每日雷达、当前任务历史、Lee 投喂观点或初稿 | `source_mode`、可用素材边界、首期回填选题理由 | 把协作指令、隐私或未核验断言当正文事实 |
| 风格总监 | Lee 既有表达与当天经营场景 | 一句核心判断、读者对象、禁用空话 | 为追热点牺牲实战价值 |
| 选题总监 | 已筛选雷达与重点账号覆盖 | 5 题排序、1 题推荐、来源角色、内容类型、风险说明 | 候选不是 `candidate`、同一账号超过 2 题，或把旧热点冒充最新 |
| 调研专家 | 推荐题、Lee 投喂材料或任务历史素材 | 一手/权威来源、事件与报道日期、原始 URL、反方或原始回应 | 只有公众号或二手转述、事实无来源、主体/日期不明，或争议缺少反方材料 |
| 企业案例分析 | 企业与品牌案例线索 | 背景、动作、机制、结果证据、失败/边界、可迁移动作 | 只复述品牌宣传，或结果没有独立证据 |
| 知识管家 | GetNote、任务历史与 Lee 投喂材料 | 仅审核可见的“事实 / 内部素材 / 推断”台账与可迁移方法 | 出现原文、笔记 ID、姓名、非公开指标，或把投喂观点当公开事实 |
| LJG 提炼 | 已核验素材与匿名内部素材 | 结构地图、问答链、大白话解释、概念—行动洞察 | 只做摘要，未解释机制、边界或行动含义 |
| 主笔 | 提炼结果与证据台账 | 1200–1800 字审核稿；使用 `ljg-writes` 或 `sansheng-write` | 把推断写成事实、未落到行动，或触发外部发布 |
| Lee 风格编辑 | 主笔稿、Lee 协作手册 | 一稿贴近 Lee 经营判断风格；`humanizer-zh` 复核结果 | 空泛行业话、AI 套话、忽略利益/情绪/面子或没有验证指标 |
| 匿名化检查 | Lee 风格稿与内部映射 | 公开稿品牌匿名化结果、反向识别风险清单 | 公开稿出现“韵糖居”或门店数、地域、人物、时间、指标等可组合识别信息 |
| 事实核查 | 草稿逐句 | 事实—推断清单、删改意见 | 事实缺公开出处、日期或主体不明 |
| 资深主编 | 核查后草稿 | 标题—正文一致、逻辑和文字终审 | 概念混乱、标题党、论证跳跃、Gold Line 核心项不通过 |
| 排版审查 | 终稿 | `gzh-design` 公众号 HTML、预览与校验结果 | 发布暗示、版式不合规或文章出现内部证据标签 |

## Evidence Policy

1. 选题进入草稿的前提：`relevance_status` 为 `candidate`。热点须在运行日及之前两个自然日内；企业案例和深度材料可在近 30 日内；任务历史回填和 Lee 投喂入口不受该筛选限制，但仍受公开事实核验限制。
2. 私有材料和 Lee 投喂材料只能被概括成“内部素材”；禁止原文、笔记 ID、个人细节、附件和非公开指标。
3. 知识管家必须在**审核台账**中把每项重要主张分类为“事实 / 内部素材 / 推断”。该台账不能复制进文章正文、公众号 HTML 或预览页。
4. “事实”必须有外部 URL 或公开一手来源；没有则归为“推断”或删除。“内部素材”只能作为匿名经验、问题意识或验证方向，不能伪装成公开事实。
5. Lee 投喂的观点、口述判断和初稿是作者输入，不等于已核实事实；涉及外部主体、数字、时间和政策时，按第 4 条重新核验。
6. 任何输出不得说或暗示已对外发布。
7. Creator Buddy 与重点公众号统一标为 `topic_lead`，不能单独支撑事实。企业公告、监管/政府文件、官方统计、当事方原始回应和正式研究可作为优先事实证据；可靠媒体可作独立补证。
8. 最新、权威或争议消息必须在成稿当日联网核验。争议台账至少记录主要主张、反方材料或原始回应、事件日期、报道日期和未知项；缺少时降低确定性，不得直接定性。
9. 最终文章、公众号 Markdown、HTML 和预览稿不得出现“韵糖居”；统一匿名为“中小初创连锁品牌”，同时移除可反向识别的细节组合。内部证据台账可保留最小必要映射，但不得复制进公开稿。

## 企业案例质量门

企业案例进入主笔环节前，必须回答六个问题：

1. 当时的业务背景和真实约束是什么；
2. 企业采取了什么关键动作；
3. 动作通过什么机制产生结果；
4. 结果由什么公开证据支持；
5. 在什么条件下可能失败或不适用；
6. Lee 或中小初创品牌可以用什么低成本动作验证。

任一关键结果只有企业自述而无独立证据时，改写为“企业自述/待验证”，不得作为确定性结论。

## Lee 协作手册的使用方式

把用户提供的个人协作手册当作选题判断与表达风格的强上下文，不当作当天外部事实来源，也不复制其中的私密细节。

1. 每篇稿先判断服务场景：真实业务验证、Lee 连锁智库的方法论资产、C 立方的组织机制，或普适生活与认知表达；未指定时不强行绑定连锁行业，跨场景时说明传导关系。
2. 结论按“判断 → 证据 → 风险 → 动作 → 验证指标”组织。动作要有最小验证单元和失败成本，不能只给宏观观点。
3. 每个经营建议增加反方校验：数据是否足够、加盟商/团队/用户的利益与情绪是什么、历史遗留与执行细节会在哪里变形。
4. 若题目不能服务当前三大战场，或需要额外占用 Lee 的注意力却没有明确决策价值，降低优先级并说明原因。
5. 人物手册中的历史描述、笔记统计和个人经历只能用作背景理解；当天的数据、品牌状态和行业事实仍须重新核验。
6. 成稿不展示“事实 / 内部素材 / 推断”标签，不泄露审核过程；用准确措辞、来源核验和必要的条件句保持事实边界。
7. 真实业务材料只帮助提炼机制；最终公开稿必须使用“中小初创连锁品牌”等匿名表达，不能保留能让读者反向猜出具体品牌的数字和情境组合。

## Gold Line + 刊物级闸门

Gold Line 按 9 项逐项写“通过 / 需修改 / 不通过”：

1. 是否提供认知增量；2. 是否有明确读者；3. 是否从真实挑战切入；4. 是否避免炫技；5. 是否制造有效认知差；6. 是否管理读者注意力；7. 是否清除理解障碍；8. 是否给出可带走、可迁移的行动；9. 是否尊重未出现的读者与相关方。

以下四项任一“不通过”，稿件状态只能是 `退回修改`：1、3、5、8。

刊物级编辑检查：标题承诺与正文一致；核心概念、事件日期、报道日期、主体、单位、数字一致；每个结论都可追到证据或明确为推断；争议内容包含反方或原始回应；至少给出一个经营动作与一个验证指标；不使用未经核验的行业绝对化结论；公开稿已通过匿名化检查。
