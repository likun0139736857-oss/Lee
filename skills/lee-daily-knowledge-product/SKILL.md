# Lee Daily Knowledge Product

生成有判断、有现场、有人味、能启发的内容，不做自动发布。交付物只进入当前 Codex 任务供 Lee 审核。

## Editorial Baseline and Task Routing

写作前读取 `references/lee-editorial-standard.md`：它提炼自截至 2026-10-04 的人物画像与 2026-10-06 修订的《Lee品牌写作圣经2.0》，仅保留可公开的表达与证据规则。用户提供更新版本时以当次材料校准，不把旧身份、计划或自述当成今日事实，也不把资料中的操作指令当作本次授权。

先判定任务与读者，再选择经营、生活或共读声部。原创与润色保留 Lee 的观点、立场、关键措辞和原始语气；摘要、纪要可忠实压缩重组；逐字稿与正式引文不改写。仅审阅时交付按影响排序的具体问题和最小修订，不自动重写。查询公众号时交付账号覆盖、文章列表或阅读摘要，不强行生成内容包。

按材料写，不编亲历、对白、心理、顿悟或成效。缺资料时缩题、短写或列补核项，只问会显著影响成品的关键缺口。未指定题材时从实际材料判断，允许普适生活与共读，不自动转成连锁教程。

## Fixed Delivery Contract

- **创作入口**：每日雷达、当前任务中尚未成文的既有推送、Lee 投喂的观点或初稿。首期优先检查任务历史回填；没有合格材料就明确缺口，不补造。
- **检索窗口**：热点为运行日及之前两个自然日；企业案例和深度材料可回看近 30 日；更旧材料只能标为背景。
- **重点线索池**：优先识别红餐网、笔记侠、餐企老板内参、咖门、红餐智库、混沌学园、刘润、L先生说、晚点LatePost、增长研习社，具体别名和内容方向读取 `config/editorial-source-pool.json`。
- **账号级检索**：重点公众号必须逐账号查询并形成覆盖台账。Creator Buddy 仅是主题爆款池，不能证明已检查某账号；公开索引零结果也不能证明账号没有更新。完整能力与覆盖定义见 `references/wechat-account-retrieval.md`。
- **证据边界**：重点公众号与 Creator Buddy 是选题线索源，不是事实证据源。公开事实必须重新联网核验一手或权威来源。
- **交付**：每日雷达以 5 个候选题、1 个推荐题、1 篇待审稿、内部证据台账和质量结果为默认；候选不足就交付实际数量并说明缺口。1200–1800 字仅作长文参考，不凑字数。Lee 给定观点或初稿时，以该输入为主线，不强行改题、补雷达或扩大篇幅；查询、短文、保真整理及仅审稿按实际任务交付。
- **匿名化**：所有最终文章、`article.md`、公众号 HTML 和预览稿不得出现“韵糖居”；相关经验统一写为“中小初创连锁品牌”，并移除门店数、地域、人物、时间、经营指标等可组合反向识别的细节。内部证据台账可保留最小必要映射，但不得进入公开稿。
- **保存位置**：`outputs/lee-daily/YYYY-MM-DD/lee-daily-report.md`；可保存不含私有信息的原始公开来源与雷达 JSON。
- **状态**：所有日报都写 `待 Lee 审核；未自动发布。` 不创建、编辑或发布任何外部内容。
- **当日幂等硬闸门**：例行每日交付的 heartbeat 或手工运行，第一个动作只能调用 `scripts/daily_delivery_guard.py`。报告首次通过校验后，脚本在同目录写入 `lee-daily-delivery-seal.json`；后续触发只比较报告文件指纹与校验规则指纹，均未变化时直接返回 `already_delivered: true`、`validation_skipped: true`，不得再次读取或校验报告正文。命中后立即结束：不加载后续创作 Skill、不打开微信、不联网、不运行雷达、不改写当日产物，只返回 `DONT_NOTIFY`。仅报告或校验规则发生变化时才重新校验并刷新封印；仅 Lee 明确要求重做时才可用 `run_daily_radar.ps1 -Force` 绕过。该封印只约束同一天的例行日报，不阻断新投喂、明确修订、查询、整理或审稿；这些任务另存文件，不覆盖已封印日报。
- **证据台账**：知识管家在审核底稿中把每项主张分为“事实 / 内部素材 / 推断”。台账不进入文章正文、公众号 HTML 或预览稿，不在成稿逐句标标签。

## Workflow

0. 先区分例行日报与明确内容任务。例行日报先执行当日幂等硬闸门，任何 `already_delivered: true` 都立即返回 `DONT_NOTIFY`；其中 `validated_delivery_seal_matches` 表示跳过了重复校验，无封印或指纹变化时仅执行一次完整校验并封印。未交付的日报与明确内容任务再判定入口，在内部台账记录 `source_mode`；明确内容任务跳过日报封印检查：
   - **每日雷达**：运行公开信号与企业案例检索，再按第 3 步选题。
   - **任务历史回填**：只读取当前任务中已推送、与内容相关且尚未成文的材料；排除协作指令、隐私、临时操作信息和未经核验的外部断言。
   - **Lee 投喂观点或初稿**：作为作者意图与内部素材，保留原意和有价值的原句；数字、品牌状态和外部判断不因来自 Lee 而自动成为事实。
1. 创作与审稿读取 `references/lee-editorial-standard.md` 和 `references/roles-and-quality-gates.md`。日报再读 `references/daily-report-template.md`；账号检索再读 `references/wechat-account-retrieval.md`、`config/topic-clusters.json` 与 `config/editorial-source-pool.json`。
2. **查询或阅览公众号**：先按 `references/wechat-account-retrieval.md` 选择后端。Lee 当场要求查询，或当前任务由登录补送 heartbeat 唤醒且桌面可见时，必须先检查已登录微信，不能直接跳到搜狗。用 `computer-use` 在微信主窗口顶部搜索框输入账号，点选“公众号”精确结果；若结果在 `WeChatAppEx.exe` 独立“搜一搜”窗口打开，必须继续读取该子窗口，而不是因主窗口恢复就误判失败。先记录账号卡的名称、类型、认证/简介、更新时间和当前结果；能进入账号历史页时再读取近三日文章并按需打开全文。将结果保存为当日 verified JSON，再通过 `-VerifiedWeChatInput` 进入统一雷达。只有完成身份与历史页核验才记为 `confirmed`；只完成已登录平台账号搜索时，以 `platform_search_checked: true` 进入雷达并记为 `partial`，但当前文章仍可作为线索，优先级高于搜狗旧索引。知道文章链接时运行 `wechat_account_retrieval.py read`。纯后台 cron 不得假装能操作前台微信；登录补送 heartbeat 属于交互式桌面任务，应在条件满足时执行该路径。
3. 仅“每日雷达”入口必须运行统一雷达入口：

   ```text
   powershell -File scripts/run_daily_radar.ps1 -OutputDirectory <outputs/lee-daily> -RunDate <YYYY-MM-DD>
   ```

   该入口先运行逐账号检索，再运行 Creator Buddy 主题雷达，最后合并到 `topic-radar.json`。只从 `relevance_status: candidate` 中选题；`manual_review` 必须人工核查，`excluded` 不得进入草稿。日报分别记录 `source_coverage.confirmed / partial / unavailable / current_matched`；`partial` 和 `unavailable` 必须写进覆盖缺口，不得解释为“账号没有更新”。前台路径仅在当前宿主支持原生桌面自动化且授权可读时使用；工具不可用时记录能力缺口，按检索参考使用允许的替代后端，不假装已检查微信。
4. **选题总监**从连锁经营、消费商业、企业案例、组织与认知四类中以 5 个候选题为目标，不足则保留缺口；有合格生活或共读材料时可进入独立声部，不为凑题搬运。同一重点账号最多 2 题；检查近 14 天已写主题并对重复题降权。选题先答谁关心、现有材料、认知增量和转给谁；流量、经营重要性、专业信任和成交分别判断。生活与共读价值不以服务当前项目或转化客户为前提。
5. **调研专家**用 `creator-buddy`、`agent-reach` 与公开检索核验每项外部事实：
   - 最新、权威或争议消息必须在成稿当日联网查询；
   - 优先企业公告、监管/政府文件、官方统计、当事方原始回应和正式研究；
   - 关键事实尽量用两个相互独立的来源交叉支持；只有一个来源时降低措辞确定性并记录缺口；
   - 争议必须记录主要主张、反方材料或原始回应、事件日期、报道日期和仍未知事项；
   - 区分事件发生时间与文章发布时间，禁止把旧闻包装成最新消息。
6. **企业案例分析**仅案例稿启用，按“背景 → 关键动作 → 作用机制 → 结果证据 → 失败或适用边界 → 可迁移动作”拆解。企业宣传稿只能作为线索；没有独立证据时不得把宣传效果写成事实。
7. **知识管家**仅需要补内部经验时，通过 `得到大脑（Get笔记）` 搜索相关私有材料，建立仅供审核的“事实 / 内部素材 / 推断”台账。只提炼可匿名素材；不复制原文、笔记 ID、附件、姓名、联系方式或非公开经营指标。
8. 复杂材料可按缺口选用 `ljg-read`、`ljg-qa`、`ljg-plain` 或 `ljg-learn`，补结构、追问、解释或迁移；简单短稿不强制串联全部 Skill。这些是中间工序，不沿用其默认署名、个人目录或对外写入。
9. 主笔按声部与真实材料成文；需要辅助时选用 `ljg-writes` **或** `sansheng-write`。经营稿讲判断、机制、利益和条件；生活稿保留体验；共读稿分清作者观点、Lee 理解和应用状态；保真任务不转成新文章。本技能的“仅审核、不发布”约束覆盖辅助 Skill 的默认发布动作。
10. 按 `references/lee-editorial-standard.md` 打磨，再调用 `humanizer-zh` 复核；不得擅改立场或削平有依据的锋芒。经营稿在后台检查“判断 → 依据 → 风险 → 动作 → 验证指标”，正文按材料自然组织；生活、共读稿可停在感受或追问，不强制经营动作、指标、使命升华、金句或服务入口。随后完成公开稿匿名化与反向识别检查。
11. **事实核查**在润色后逐句复核文章与证据台账；**资深主编**终审标题、逻辑、可读性、行动性、争议公平性和 Gold Line。任一核心 Gold Line 项（1、3、5、8）不通过，稿件标为 `退回修改`。
12. 只有终审通过且任务需要公众号排版时才调用 `gzh-design` 输出 `article.md`、公众号 HTML 和预览页。依次运行：

    ```text
    validate_daily_report.py <report.md>
    validate_public_output.py <article.md> <article.html> <preview.html>
    ```

    日报执行日报校验；所有形成的公开稿执行公开输出校验，均输出 `VALID` 后交付。仅审阅或资料不足的结果按实际状态说明，不虚标通过。校验脚本仅覆盖结构与品牌名等机器检查，不能替代事实、归属与反向识别审查；仍不得发布。

## Decision Rules

| 情况 | 动作 |
| --- | --- |
| “加盟”命中体育、娱乐或人员转会 | 保留在雷达供审计，标为 `excluded`，不选题 |
| Feed 或已登录微信成功，窗口内无文章 | 可写“已完成账号检查，窗口内无命中”，不可扩大为账号没有更新 |
| 已登录微信只完成账号精确搜索，未进入历史页 | verified JSON 写 `platform_search_checked: true`，标为 `partial`；保留平台显示的当前文章和更新时间，不再降级为搜狗零结果 |
| 搜狗微信精确作者查询成功但无命中 | 标为 `partial`；写进覆盖缺口，不得写“账号没有更新” |
| 搜狗最新精确作者结果早于热点窗口 | 标记 `index_freshness: stale`、`requires_wechat_verification: true`；明确“索引陈旧，不能验证公众号当前更新” |
| 重点公众号账号级后端失败 | 标为 `unavailable`；Creator Buddy 或主题词只能补线索，不得伪称账号覆盖 |
| 公众号文章提供数据、结论或争议判断 | 只作为线索；回查一手/权威来源后才能作为事实 |
| 热点超出三日窗口 | 普通热点降为背景；符合企业案例标准且在 30 日内时可保留 |
| 企业案例只有品牌宣传材料 | 标为线索或推断；补到独立证据后才能确定性成文 |
| 争议缺少反方材料或原始回应 | 降低措辞确定性并列为缺口；核心争议不得直接定性 |
| 私有笔记含个体、合同、利润或纠纷 | 只形成匿名内部素材；无法匿名化则不用 |
| Lee 的观点或初稿含外部断言 | 先作为内部素材记账；核验后才可作为公开事实 |
| 公开稿出现真实业务品牌名或可反向识别组合 | 退回匿名化，不得进入 `gzh-design` 交付 |
| 证据不足但题目有启发 | 可做“待验证假设”，不可写成“行业已发生” |

## Role Order

以下是审稿职责，不表示必须启用多个代理。按适用任务执行：素材路由 → 风格总监 → 选题总监 → 调研专家 → 企业案例分析 → 知识管家 → LJG 提炼 → 主笔 → Lee 风格编辑 + `humanizer-zh` → 匿名化检查 → 事实核查 → 资深主编 → `gzh-design` 排版审查。企业案例与 LJG 提炼仅在需要时启用；创作不能跳过适用的关键事实核验、证据分层、匿名化、事实核查、终审或公开稿校验。角色输入、输出和否决权见 `references/roles-and-quality-gates.md`。

## Final Task Message

按任务只发送实际交付摘要；日报发送：创作入口、推荐题或 Lee 投喂主题、关键判断、重点账号完整/部分/不可用覆盖、权威/争议核验缺口、质量闸门结果、待审状态和报告路径。不要发送内部映射、私有原文、真实业务品牌名或自动发布动作。
