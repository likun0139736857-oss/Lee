# Lee Daily Knowledge Product

生成经营判断与认知产品，不做自动发布。交付物只进入当前 Codex 任务供 Lee 审核。

## Fixed Delivery Contract

- **创作入口**：每日雷达、当前任务中尚未成文的既有推送、Lee 投喂的观点或初稿。首期优先检查任务历史回填；没有合格材料就明确缺口，不补造。
- **检索窗口**：热点为运行日及之前两个自然日；企业案例和深度材料可回看近 30 日；更旧材料只能标为背景。
- **重点线索池**：优先识别红餐网、笔记侠、餐企老板内参、咖门、红餐智库、混沌学园、刘润、L先生说、晚点LatePost、增长研习社，具体别名和内容方向读取 `config/editorial-source-pool.json`。
- **证据边界**：重点公众号与 Creator Buddy 是选题线索源，不是事实证据源。公开事实必须重新联网核验一手或权威来源。
- **交付**：5 个候选题、1 个推荐题、1 篇 1200–1800 字待审稿、内部证据台账、质量闸门结果。Lee 明确给定观点或初稿时，以该输入为主线，不强行改题。
- **匿名化**：所有最终文章、`article.md`、公众号 HTML 和预览稿不得出现“韵糖居”；相关经验统一写为“中小初创连锁品牌”，并移除门店数、地域、人物、时间、经营指标等可组合反向识别的细节。内部证据台账可保留最小必要映射，但不得进入公开稿。
- **保存位置**：`outputs/lee-daily/YYYY-MM-DD/lee-daily-report.md`；可保存不含私有信息的原始公开来源与雷达 JSON。
- **状态**：所有日报都写 `待 Lee 审核；未自动发布。` 不创建、编辑或发布任何外部内容。
- **证据台账**：知识管家在审核底稿中把每项主张分为“事实 / 内部素材 / 推断”。台账不进入文章正文、公众号 HTML 或预览稿，不在成稿逐句标标签。

## Workflow

0. 判定创作入口，并在内部台账记录 `source_mode`：
   - **每日雷达**：运行公开信号与企业案例检索，再按第 3 步选题。
   - **任务历史回填**：只读取当前任务中已推送、与内容相关且尚未成文的材料；排除协作指令、隐私、临时操作信息和未经核验的外部断言。
   - **Lee 投喂观点或初稿**：作为作者意图与内部素材，保留原意和有价值的原句；数字、品牌状态和外部判断不因来自 Lee 而自动成为事实。
1. 读取 `references/roles-and-quality-gates.md`、`references/daily-report-template.md`、`config/topic-clusters.json` 与 `config/editorial-source-pool.json`。
2. 仅“每日雷达”入口必须运行 `scripts/run_creator_buddy.ps1`，再运行：

   ```text
   prepare_topic_radar.py <data.json> <topic-clusters.json> <editorial-source-pool.json> <radar.json> <YYYY-MM-DD>
   ```

   只从 `relevance_status: candidate` 中选题；`manual_review` 必须人工核查，`excluded` 不得进入草稿。`source_coverage.missing` 必须写进覆盖缺口，不得声称已抓到未命中的公众号。
3. **选题总监**从连锁经营、消费商业、企业案例、组织与认知四类中形成 5 个候选题。同一重点账号最多 2 题；检查近 14 天已写主题并对重复题降权。热点不能因为流量高而覆盖更有决策价值的题目。
4. **调研专家**用 `creator-buddy`、`agent-reach` 与公开检索核验每项外部事实：
   - 最新、权威或争议消息必须在成稿当日联网查询；
   - 优先企业公告、监管/政府文件、官方统计、当事方原始回应和正式研究；
   - 关键事实尽量用两个相互独立的来源交叉支持；只有一个来源时降低措辞确定性并记录缺口；
   - 争议必须记录主要主张、反方材料或原始回应、事件日期、报道日期和仍未知事项；
   - 区分事件发生时间与文章发布时间，禁止把旧闻包装成最新消息。
5. **企业案例分析**按“背景 → 关键动作 → 作用机制 → 结果证据 → 失败或适用边界 → 可迁移动作”拆解。企业宣传稿只能作为线索；没有独立证据时不得把宣传效果写成事实。
6. **知识管家**通过 `得到大脑（Get笔记）` 搜索相关私有材料，建立仅供审核的“事实 / 内部素材 / 推断”台账。只提炼可匿名素材；不复制原文、笔记 ID、附件、姓名、联系方式或非公开经营指标。
7. 对已核验素材依次调用 `ljg-read`、`ljg-qa`、`ljg-plain` 和 `ljg-learn`，产出结构地图、问答链、大白话解释和概念—行动洞察。这些是中间工序，不沿用其默认署名、个人目录或对外写入。
8. 主笔调用 `ljg-writes` **或** `sansheng-write` 成文：前者适合单一判断，后者适合完整长文工作流。本技能的“仅审核、不发布”约束覆盖其他 Skill 的默认发布动作。
9. 进行 Lee 专属风格打磨，再调用 `humanizer-zh`：从真实场景切入，写清“判断 → 依据 → 风险 → 动作 → 验证指标”，保留不确定性与反方校验；不强行绑定连锁行业，未指定时允许从普适生活、组织或认知切入。随后完成公开稿匿名化与反向识别检查。
10. **事实核查**在润色后逐句复核文章与证据台账；**资深主编**终审标题、逻辑、可读性、行动性、争议公平性和 Gold Line。任一核心 Gold Line 项（1、3、5、8）不通过，稿件标为 `退回修改`。
11. 只有终审通过后才调用 `gzh-design` 输出 `article.md`、公众号 HTML 和预览页。依次运行：

    ```text
    validate_daily_report.py <report.md>
    validate_public_output.py <article.md> <article.html> <preview.html>
    ```

    两项均输出 `VALID` 才能在当前任务推送摘要与文件链接；仍不得发布。

## Decision Rules

| 情况 | 动作 |
| --- | --- |
| “加盟”命中体育、娱乐或人员转会 | 保留在雷达供审计，标为 `excluded`，不选题 |
| 重点公众号无命中 | 写进覆盖缺口；改用其主题关键词补检，但不得伪称抓到该账号文章 |
| 公众号文章提供数据、结论或争议判断 | 只作为线索；回查一手/权威来源后才能作为事实 |
| 热点超出三日窗口 | 普通热点降为背景；符合企业案例标准且在 30 日内时可保留 |
| 企业案例只有品牌宣传材料 | 标为线索或推断；补到独立证据后才能确定性成文 |
| 争议缺少反方材料或原始回应 | 降低措辞确定性并列为缺口；核心争议不得直接定性 |
| 私有笔记含个体、合同、利润或纠纷 | 只形成匿名内部素材；无法匿名化则不用 |
| Lee 的观点或初稿含外部断言 | 先作为内部素材记账；核验后才可作为公开事实 |
| 公开稿出现真实业务品牌名或可反向识别组合 | 退回匿名化，不得进入 `gzh-design` 交付 |
| 证据不足但题目有启发 | 可做“待验证假设”，不可写成“行业已发生” |

## Role Order

按以下顺序执行：素材路由 → 风格总监 → 选题总监 → 调研专家 → 企业案例分析 → 知识管家 → LJG 提炼 → 主笔 → Lee 风格编辑 + `humanizer-zh` → 匿名化检查 → 事实核查 → 资深主编 → `gzh-design` 排版审查。不能跳过调研核验、证据分层、匿名化、事实核查、终审或公开稿校验。角色输入、输出和否决权见 `references/roles-and-quality-gates.md`。

## Final Task Message

只发送：创作入口、推荐题或 Lee 投喂主题、关键判断、重点账号覆盖缺口、权威/争议核验缺口、质量闸门结果、待审状态和报告路径。不要发送内部映射、私有原文、真实业务品牌名或自动发布动作。
