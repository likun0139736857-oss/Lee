# lee-daily-knowledge-product 使用说明

## 这个 Skill 做什么

每天为 Lee 生成一份仅供审核的知识产品：5 个候选题、1 个推荐题、1 篇待审长文、内部证据台账、公众号排版稿和质量闸门结果。不会自动发布到公众号或其他平台。

## 四种使用方式

### 1. 每日选题与成稿

```text
使用 $lee-daily-knowledge-product，生成今天的选题雷达和待审稿。
```

系统会检索近 3 日热点和近 30 日企业案例，优先识别红餐网、笔记侠、餐企老板内参、咖门、红餐智库、混沌学园、刘润、L先生说、晚点LatePost、增长研习社。

### 2. 解剖优秀企业案例

```text
使用 $lee-daily-knowledge-product，找一个近期优秀企业案例，核验公开事实后拆成一篇文章。
```

案例固定拆解为：背景、关键动作、作用机制、结果证据、失败或适用边界、可迁移动作。

### 3. 投喂观点或初稿

```text
使用 $lee-daily-knowledge-product，这是我的观点/初稿：……请保留原意，补调研、核验并写成待审稿。
```

Lee 的观点作为作者意图和内部素材；其中涉及数字、企业、政策、时间或市场状态的断言仍会联网核验。

### 4. 从当前任务的既有推送回填

```text
使用 $lee-daily-knowledge-product，从当前任务之前尚未成文的推送中选择最有价值的一条，写成待审稿。
```

系统只读取当前任务中与内容相关的材料，不把协作指令、隐私或临时操作信息当作文章事实。

## 证据与争议规则

- 指定公众号和 Creator Buddy 只负责提供选题线索，不能单独证明事实。
- 最新、权威或争议消息在成稿当日联网查询。
- 优先企业公告、监管或政府文件、官方统计、当事方原始回应和正式研究。
- 关键事实尽量交叉核对两个独立来源。
- 争议内容必须同时记录主要主张、反方材料或原始回应、事件日期、报道日期和未知项。

## 品牌匿名化

所有公开文章、公众号 Markdown、HTML 和预览稿不得出现真实业务品牌名“韵糖居”，统一写为“中小初创连锁品牌”，并删除可能反向识别品牌的门店数、地域、人物、时间和经营指标组合。内部证据台账可保留最小必要映射，但不会进入成稿。

## 输出与审核

默认输出目录：

```text
outputs/lee-daily/YYYY-MM-DD/
```

主要文件：

- `lee-daily-report.md`：选题雷达、待审稿、内部证据台账和质量结果；
- `article.md`：不含内部标签的公开稿；
- 公众号 HTML 与预览页：由 `gzh-design` 生成；
- 雷达 JSON：记录账号命中、内容类型、窗口、来源角色和覆盖缺口。

只有日报校验和公开稿匿名化校验同时输出 `VALID`，状态才可写为：

```text
待 Lee 审核；未自动发布。
```

## 安装与更新

仓库目录：

```text
skills/lee-daily-knowledge-product/
```

将该目录完整复制到：

```text
%USERPROFILE%\.codex\skills\lee-daily-knowledge-product\
```

更新时保留整个目录结构，包括 `SKILL.md`、`agents/`、`config/`、`references/`、`scripts/` 和 `tests/`。

## 依赖与已知边界

- 依赖 Creator Buddy、公开联网检索、GetNote、`ljg-read`、`ljg-qa`、`ljg-plain`、`ljg-learn`、`ljg-writes` 或 `sansheng-write`、`humanizer-zh`、`gzh-design`。
- Creator Buddy 返回的是公众号爆款/赛道数据，不是某一公众号的完整历史文章库。重点账号未命中时会明确写覆盖缺口，不会伪造抓取结果。
- 本 Skill 只生成待审内容，不执行发布、评论、点赞、关注或私信。
