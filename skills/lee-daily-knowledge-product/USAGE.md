# lee-daily-knowledge-product 使用说明

按 Lee 的表达与证据基准制作待审内容：经营稿有判断、利益与承接，生活稿保留体验，共读稿分清来源。不会自动发布。写作规则提炼自截至 2026-10-04 的画像与 2026-10-06 修订的《Lee品牌写作圣经2.0》，详见 `references/lee-editorial-standard.md`；原始私人资料不随包分发。

## 常用入口

| 请求 | 实际交付 |
| --- | --- |
| “生成今天的选题雷达和待审稿” | 近三日热点、近30日企业案例；默认5个候选、1个推荐、待审稿与内部台账，不足不凑数 |
| “找一个近期企业案例，核验后写文章” | 背景、动作、机制、结果证据、边界及可迁移判断；研究案例不写成亲历 |
| “这是我的观点/初稿，请保留原意润色” | 以输入为主线，不强制雷达；保留立场、语气和关键措辞，核验外部断言 |
| “写这段生活感悟/读书心得” | 生活或共读声部；不编亲历，不硬塞经营动作、指标或广告 |
| “从当前任务尚未成文的推送回填” | 只用当前任务的相关材料，排除协作指令、隐私与临时操作信息 |
| “查这个公众号最近发了什么/读这篇文章” | 账号覆盖、文章列表或阅读结果，不强制创作内容包 |
| “整理/仅审阅这篇稿” | 忠实整理，或按影响列具体问题与最小修订；逐字稿与正式引文不改写 |

调用时写 `使用 $lee-daily-knowledge-product` 并提供实际材料；有特别保留、长度或渠道要求再说明。1200–1800 字仅作长文参考，字数、金句、三幕与日更都不是通用验收条件。

## 证据、隐私与审核

- 公众号和 Creator Buddy 是线索池；关键公开事实回查一手/权威来源，争议核对原始回应、反方、日期与未知项。
- 逐账号记录 `confirmed / partial / unavailable`。搜狗微信索引只算部分覆盖；零结果不能证明账号未更新。
- 私有素材在内部台账分层；原稿可保留有来源的表达，私人笔记原文、ID、客户信息与非公开指标不进入公开稿。
- 相关内部品牌经验匿名为“中小初创连锁品牌”，公开稿不出现“韵糖居”，并人工检查可反向识别的细节组合；公开研究案例按核验来源引用。
- 分开计划、交付、实际结果和因果贡献，不用品牌整体规模证明个人成绩。
- 内容终审与脚本校验分别执行。`VALID` 仅证明脚本覆盖的结构和品牌名等项目，不替代事实与人工匿名化审查。

## 输出与重复运行

日报默认保存到当前任务 `outputs/lee-daily/YYYY-MM-DD/lee-daily-report.md`，包含选题、待审稿、内部台账和质量记录。公开稿为 `article.md`；需要公众号排版且终审通过时生成 HTML 与预览页。状态：`待 Lee 审核；未自动发布。`

例行日报先运行 `scripts/daily_delivery_guard.py`；当天合格报告已封印且指纹未变时立即结束，不重复读取、检索或改写。明确新投喂、修订、查询与审稿另存文件，不受日报封印阻断；只有 Lee 明确要求重做日报时才使用 `-Force`。

## 安装与依赖

仓库目录为 `skills/lee-daily-knowledge-product/`。完整复制到 `%USERPROFILE%\.codex\skills\lee-daily-knowledge-product\`，保留 `agents/`、`config/`、`references/`、`scripts/` 与 `tests/`。

日常检索按环境使用 Feed、公开检索、Creator Buddy 或已授权的登录微信读取；原生桌面自动化不可用时报告能力缺口并使用允许的替代后端，不假装完成检查。GetNote 仅在需要补私有素材时使用；LJG 与写作辅助 Skill 按实际缺口选用，不强制全部加载。公众号排版使用 `gzh-design`，不扩展为发布、评论或私信授权。
