# 动态增量更新流程

## 触发

1. 用户主动放入新文件/文件夹并要求更新
2. 定时巡检（如每周六 10:00，由定时任务触发）

## 执行步骤

1. **扫描**：对比上次更新记录，识别语料目录新增/修改文件（按新增或修改时间判断）；无新增 → 在更新日志写「本周无新增」并结束
2. **蒸馏**：对新增内容按 RIA++ 六段式蒸馏为自包含学习模块（含自测题/闪卡/知识图卡/四问/一页纸/推荐书单）
3. **归入阶段**：按主题归入 01-08 对应阶段；主题不符可新增阶段或归入最接近阶段并在 README 说明。**新增 vs 回填判断**：新素材与既有模块呈"方法论→题库/工具/案例库"递进关系、或内容独立成册可自成体系 → 优先新增模块；与既有模块高度重叠、仅补充细节 → 回填既有模块并说明回填去向
4. **更新 md 体系**：阶段 README 模块清单/进度表、00 总纲阶段详情与学时、学习进度总表
5. **重建站点**：用 build_html.py 重新生成 index.html（保持单文件/离线/localStorage 兼容）
6. **写更新日志**：扫描时间、新增文件清单、新增模块数、更新文件清单、验证结果
7. **验证**：node --check + 浏览器实测（新模块渲染、进度公式、既有功能回归）

## 硬性边界（学习记录保护）

- 浏览器 localStorage 中的学习状态、四问笔记、测评记录、待重思、复盘卡、书单标记等**一律不读取、不写入、不覆盖、不迁移**
- 更新只做「新语料 → 新模块 → 站点生成」的单向蒸馏
- 原始语料零改动；既有 md 只增不改

## 无法读取文件

扫描件/损坏文件如实标注到对应阶段待精读清单（相对路径 + 原因 + 优先级），不编造内容。

## 更新日志格式

```markdown
# 学习看板更新日志

## YYYY-MM-DD（周X）· 第N次更新
- 触发：定时/用户主动
- 扫描范围：…
- 扫描结果：新增 X 个文件 / 本周无新增
- 新增模块：…
- 更新文件清单：…
- 验证结果：…
- 说明（透明记录缺口，如有）：…
```
